# Skill: Doc Consistency

> 같은 회사용으로 작성된 여러 문서(career/resume/coverletter) 간 표현 불일치와 사실 충돌을 확인하는 절차

---

## 언제 이 스킬을 쓰는가

- 같은 회사용 문서를 여러 개 작성한 뒤 제출 전 최종 점검할 때
- 한 문서를 수정한 뒤 다른 문서에 동일한 수정이 필요한지 확인할 때

---

## 확인 절차

### Step 1. 대상 파일 확인

`_output/{company}/` 폴더 내 HTML 파일 전체를 읽는다.

### Step 2. 비교 기준 목록 작성

각 파일에서 아래 항목을 추출한다:

- 수치가 있는 성과 (예: "9시간 → 1시간", "3~4분 → 수초")
- 트러블슈팅 사건 서술 (원인·해결 방법)
- 기술 선택 이유 서술
- 강점/태도 관련 표현
- 재직 기간·역할 표기

### Step 3. 불일치 탐지

추출한 항목을 문서 간 대조해 아래 두 종류를 구분한다:

**사실 충돌** — 같은 사건인데 수치·내용이 다른 경우 (반드시 수정)
```
예: career에서 "9시간 → 1시간", resume에서 "8시간 → 1시간"
```

**표현 불일치** — 같은 내용인데 강도·어조·용어가 다른 경우 (선택적 수정)
```
예: career에서 "발견하고 원인 특정", resume에서 "단독 원인 특정"
예: career에서 "커스텀 커맨드", coverletter에서 "커스텀 슬래시 커맨드"
```

### Step 4. 결과 제시

불일치 항목을 아래 형식으로 정리해서 제시한다:

```
[사실 충돌 — 수정 필요]
- 항목명
  career: ...
  resume: ...

[표현 불일치 — 선택적 수정]
- 항목명
  career: ...
  coverletter: ...
```

불일치가 없으면 "세 문서 간 충돌 없음"으로 보고한다.

### Step 5. 수정 진행

사용자 확인 후 지정한 파일들을 수정한다.

---

## 주의사항

- 문서 유형에 따라 의도적인 압축·생략이 있을 수 있다 (resume는 짧게, career는 상세하게).
  표현 길이 차이는 불일치로 보지 않는다.
- 사실이 다른 것(수치, 사건 내용)만 반드시 수정 권장하고, 표현 차이는 사용자가 결정하도록 한다.
